# SCCB 寄存器读回诊断

目的：已有诊断为 0x008F，说明 FPGA 侧配置完成、VSYNC/HREF 变化、WR 曾打开，但 WR 与 HREF 无重叠、有效行数 0。实物丝印已确认，用户确认接线与丝印一致。本版不反转任何极性，不改寄存器初始化值，先读取证据。

## 操作

保留 HREF→JC10、RST→JC9 及上拉，其他接线不变。下载最新 `build/vivado/stream_top.bit`。

所有开关设 0，仅将 **SW14=1、SW12=1**；SW13 保持 0。按 BTNC，等待 3 秒。以下四次仅改变 SW11/SW10，不用重复按复位，不需要串口程序：

| SW11 | SW10 | 读取寄存器 | LED15..LED8 的预期值 |
|---|---|---|---|
| 0 | 0 | PID 0x0A | 0x76 = 0111 0110 |
| 0 | 1 | COM10 0x15 | 0x02 = 0000 0010 |
| 1 | 0 | TSLB 0x3A | 0x0C = 0000 1100 |
| 1 | 1 | COM7 0x12 | 0x00 = 0000 0000 |

每次报告完整 LED15→LED0 共 16 位，不能只报告高字节。以上预期是原配置应读回的值，并非已经从你的模组确认读到。

## 此页面低 8 位

| LED | 含义 |
|---|---|
| 0 | 原 SCCB 写配置流程完成 |
| 1 | 四个寄存器读回流程完成 |
| 2 | 读回地址/寄存器指针事务观察到无低电平 ACK；此时不应把高字节当可靠读数 |
| 3 | 配置完成后，曾在 HREF 上升沿观察到 VSYNC=1 |
| 4 | 配置完成后，曾在 HREF 上升沿观察到 VSYNC=0 |
| 5 | 原采集状态机 VSYNC 等待超时 |
| 6 | 原 SCCB 写配置错误 |
| 7 | RST 拉低和释放后的等待已完成 |

LED3/4 表示 HREF 上升沿处的 VSYNC 状态，不是整段高电平的持续时间测量。正常负 VSYNC 配置预期 LED3=1、LED4=0，但必须以实测为准。若两者都亮，可能涉及初始化过渡、接线信号、极性或输出异常，不能仅凭一个标志自动改变 WRST。

SW14=1、SW12=0 仍是上一版行数诊断页；SW14=0 仍为普通工作指示。SW11、SW10、SW12 只切换显示页面，不修改摄像头设置。

## 实现与边界

读回逻辑在原配置完成并释放总线后启动一次，BTNC 后重跑。使用 7 位地址 0x21，即写 0x42 + 寄存器地址 + STOP，随后读 0x43 + 一字节 + 主机 NACK + STOP。每个阶段开漏驱动；顶层将两个 sequencer 的拉低请求合并到每根引脚的唯一物理驱动。原采集流程与图像协议未改变。

本版读回是诊断，不是自动纠错；即使读回值不符合预期，也不会自动修改配置。ACK 检查采用常见 OV7670 模组的响应约定，SCCB 第九位的兼容性差异仍需结合实际设备判断。

camera_readback 位于现有 `rtl/camera_config.sv` 内，monitor 位于 `rtl/stream_top.sv` 内；已有 Vivado 工程不需要额外添加设计源文件。新增 `sim/tb_camera_readback.sv` 仅用于仿真。

参考：[现有 OV7670 FIFO SCCB 驱动的 STOP 分隔读事务](https://github.com/har-in-air/ov7670fifo/blob/master/main/sccb.c)，[OV7670 数据手册](https://www.voti.nl/docs/OV7670.pdf)。
