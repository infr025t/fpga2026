# 固定噪声诊断（2026-10-05）

## 已知证据

早期 camera_gray 5 帧、camera_change 10 帧的像素完全相同，SHA256 为 a9430cff6c85f5fe14fca50e7a3a2635a76eea00d11b94a600f3ed4344f8fc70。

camera_rst_test 目录里有两组结果：77～86 帧为已知 FPGA 内部测试图；随后 8～17 帧的像素又全部相同，SHA256 为 eb748b4174ffc4d11725802a5772a1f6fcb07372590e9a1b1f080e5a9c8df22f。用户确认这两组来源差异是切换 SW0 所致，不能视为摄像头恢复更新的证据。后者与最初旧噪声不同，但仍不随遮挡变化。这支持“FIFO 未正常更新”的排查方向，不足以单独确定接线或 RTL 的具体错误。

## 本次改动只增加观测

1. 新增 HREF 输入：摄像头 HREF → **JC10（R18）**，其余接线不变，断电接线。
2. 双触发器同步后，记录 VSYNC/HREF 的变化、FPGA 内部写使能及其与 HREF 的重叠。
3. 每个 WR 高电平窗口内统计 HREF 上升沿数，在 WR 下降时锁存，饱和到 65535。
4. **没有改变 SCCB 寄存器、FIFO 读写状态机或数据协议。** HREF 仅用于观察，仍依赖模组内部有效行写入门控。
5. SW14=0 保持原 LED 显示；SW14=1 切换为下表。SW13 选择行计数高/低字节，不影响处理。

## 操作

断电接 HREF→JC10。上电下载 `build/vivado/stream_top.bit` 新版。所有 SW=0，再只将 SW14=1。按 BTNC，等待至少 3 秒，拍 LED 区照片，务必带上 LED 编号。然后 SW13=1 再拍一张；或直接报告哪些 LED 亮。

| LED | SW14=1 的含义 |
|---|---|
| 0 | SCCB 写配置完成 |
| 1 | 配置完成后观察到 VSYNC 电平变化，锁存到复位 |
| 2 | 配置完成后观察到 HREF 电平变化，锁存到复位 |
| 3 | FPGA 内部曾置 WR=1，锁存到复位 |
| 4 | 曾观察到 WR=1 且 HREF=1，锁存到复位 |
| 5 | 采集等待 VSYNC 超时（原 cap_error 状态） |
| 6 | SCCB 配置错误 |
| 7 | 摄像头 RST 拉低及释放后等待阶段已完成 |
| 8～15 | 最近完成的 WR 窗口中 HREF 上升沿数量；LED8 是所选字节 bit0 |

SW13=0 显示低 8 位；SW13=1 显示高 8 位。正常 QVGA 完整帧预期 240（0x00F0）：低字节 LED12～15 亮、LED8～11 灭，高字节 LED8～15 全灭。若没有完成采集，计数仍为 0；因此必须同时看 LED3 和低位状态，不能孤立判断。

诊断 LED 是 FPGA 侧证据：LED3 亮不能证明 JC4 的电平真的到达 FIFO 写使能引脚，240 行也不能证明 PCLK 和数据正确写入。若只有 VSYNC 变化但没有 HREF，需要查 HREF 线路、配置或摄像头输出；若 HREF 存在但 WR 窗口中计数为 0，需核查帧极性与写入窗口；若 240 行且图像仍固定，重点转向模块内部门控、写时钟、WR/WRST 实际电气连接及 FIFO 数据路径。

HREF 缺线时内部弱下拉使监测保持低电平，不会改变原图像路径。这个版本是诊断工具，**尚未修复或证明解决真实摄像头固定噪声问题**。
