## 开关与模式

### 正常页：SW14=0

采集源、图像模式、阈值和输出选项在下一帧启动前锁存；诊断LED页面随选择开关变化。SW15控制是否启动后续帧，BTNC触发整机复位，可能中断当前串口包。

| 控制 | 含义 |
|---|---|
| SW0 | 0：摄像头；1：内部测试图 |
| SW1 | 0：灰度；1：Sobel边缘图 |
| SW2 | 0：关闭定位；1：开启ROI单目标定位 |
| SW3 | 0：暗目标，Y≤目标阈值；1：亮目标，Y≥目标阈值 |
| SW7:4 | Sobel阈值：0000→160；非零数值N→64×N，例如0100→256 |
| SW9:8 | 目标亮度阈值：00→96、01→64、10→128、11→160 |
| SW10 | 1：请求1 bit打包，仅SW1=1时生效 |
| SW11 | 1：请求仅定位结果，仅SW2=1时生效；配合SW13定期插入预览图 |
| SW12 | 1：快速帧间模式；默认跳过每帧额外500 ms等待，首次启动等待仍保留 |
| SW13 | 1：在仅定位结果模式中启用周期预览；诊断页仍选择行数的高/低字节 |
| SW14 | 0：正常页；1：诊断页，SW10/11/12改作诊断选择 |
| SW15 | 1：暂停后续采集，当前帧继续完成；0：恢复启动新帧 |
| BTNC | 复位帧序号、处理和发送状态，并重新初始化摄像头 |

### 常用组合

下面仅列出需要置1的开关，其余置0；示例使用摄像头和默认暗目标阈值。增加SW0=1可切换为内部测试图。

| 目的 | 置1的开关 | 协议 / PC文件 |
|---|---|---|
| 灰度预览 | 无 | v1；PGM、JSON、CSV |
| Sobel预览 | SW1 | v1；PGM、JSON、CSV |
| 灰度图附带定位 | SW2 | v2；PGM、JSON、CSV |
| 打包边缘图附带定位 | SW1、SW2、SW10 | v3；展开后的PGM、JSON、CSV |
| 快速回传定位结果 | SW2、SW11、SW12 | v3；JSON、CSV |
| 快速定位并定期预览灰度图 | SW2、SW11、SW12、SW13 | v2图像与v3结果混合；图像帧另存PGM |
| 快速定位并定期预览打包边缘图 | SW1、SW2、SW10、SW11、SW12、SW13 | v3图像与结果混合；图像帧另存展开后的PGM |

打包也可关闭SW2单独使用。灰度模式会忽略打包请求；关闭定位时会忽略仅结果请求。仅结果帧不带图像，打包只对图像帧生效。进入诊断页后，新帧的打包、仅结果、快速模式和周期预览请求均按关闭处理，SW1图像模式与SW2定位仍生效，当前帧保持已锁存的设置。

### 高速定位与周期预览

正常页SW2=1、SW11=1时，打开SW13启用周期预览。默认先发送一张新图，随后发送15个仅定位结果包，再发送新图。每个包均包含本次采集的目标统计。周期按成功发送计数，暂停和采集超时不会消耗次数。关闭再启用预览、切换采集源或灰度/Sobel模式、修改Sobel阈值，或改变内部测试图明暗极性时，下一帧重新从预览开始。

SW10可让Sobel预览图按1 bit打包；灰度预览始终使用8位像素。预览图占用图像传输时间，因此对应两次定位结果之间的间隔会变长，不应将其视为连续视频。当前仍采用串行采集、处理与发送。

318×238图像含定位信息时，8位完整包为75,758字节，1 bit包为9,535字节，仅结果包为74字节。后两者在1 Mbps、8N1下的理想线路时间约为95.35 ms和0.74 ms；整机还需采集、FIFO读出、处理和帧同步，不能据此直接换算实际帧率。

## PC输出

### 实时显示与退出

```powershell
python -m pip install opencv-python
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --display
```

省略 `--count` 可持续接收；按Ctrl+C结束，显示窗口内也可按q退出。显示用黄色标出ROI、绿色标出目标框、红色标出目标中心；无有效目标时显示“No target”。仅结果模式显示带“Features only”标注的空白定位画布。

配合周期预览，可在最近一张图上显示新的定位结果：

```powershell
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --display --hold-preview
```

`Preview frame=... (held)`标明历史背景，`Target frame=...`标明当前定位帧；两者来自不同采集时刻。尺寸、图像模式、阈值改变，或帧序号倒退/重复时清空缓存，收到新图后重建。协议没有采集源或会话标志，漏包后的源切换无法全部识别，应以显示帧号为准。此选项必须与`--display`一起使用，仅改变窗口，不会为仅结果帧保存旧图或修改JSON/CSV。

串口收到首字节后只读取当前已到达的数据，避免短定位包等待凑满4096字节或0.25秒读取超时。无数据时仍保留读取超时，用于退出按键和空闲恢复。

### 持续接收、断线重连与原始录制

需要长时间采集或保留原始数据排查问题时：

```powershell
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --reconnect 1 --record-wire recordings/session.bin
```

`--reconnect`为重试间隔秒数，默认0关闭。启用后，端口暂时不可用或串口读出错误会在指定间隔后重试同一个端口；如果重新插接后COM编号改变，需要修改`--port`。暂停输出或短暂无字节不会触发重新连接，截断包的空闲恢复仍由`--idle-resync`控制。

连接断开是明确的旧流边界：先恢复缓冲中完整且CRC有效的包，再丢弃未完成尾帧并清空显示预览。开启显示时窗口会清空并标注“Disconnected - retrying”；重试等待期间也可按q，终端可按Ctrl+C退出。`--count`累计所有连接收到的有效帧，不会在重连时归零。默认不重连时，串口I/O错误以非零状态退出，已保存帧保留。

`--record-wire`仅用于串口输入，记录实际读取的字节，包含噪声、CRC错误数据和半帧。第一段保存为指定路径，后续成功连接另开`session_001.bin`、`session_002.bin`等文件；已有编号会跳过，已有首文件则拒绝启动，避免覆盖记录。每次读取后刷新文件缓冲。磁盘录制或图像保存失败会明确报错并退出。

每段分别回放即可保留连接边界：

```powershell
python pc/receiver.py --input recordings/session.bin --out replay_session
python pc/receiver.py --input recordings/session_001.bin --out replay_session_001
```

断线前的一段可能以半帧结束，回放会在保存合法完整帧后报告“incomplete frame”。`--display --hold-preview`仍可与重连、录制一起使用；新连接的首张图到达前不会沿用旧连接的背景。

### 保存内容

| 文件 / 字段 | 内容 |
|---|---|
| `frame_*.pgm` | 灰度/Sobel图；1 bit数据展开为0/255保存，显示叠加不会写入PGM |
| `frame_*.json` | 每帧元数据；`target`保存ROI、面积、坐标和、有效性与目标中心 |
| `metadata.csv` | 各帧统计汇总；旧表头或编码不兼容时另写 `metadata_v3.csv` 或后续编号 |
| `pixel_format` | `gray8`：8位灰度或Sobel图；`mono1`：打包边缘图；`none`：仅结果 |
| `image_file` | 对应PGM文件名；仅结果模式为null，且不创建PGM |
| 顶层 `centroid_x/y` | 亮像素质心；目标中心应读取 `target.centroid_x/y` |

接收器兼容FPG1 v1/v2/v3混合流。板端复位导致frame_id重复时，文件名自动增加后缀，保留已有图像和元数据。

## ROI与运行参数

定位采用ROI内的亮度阈值统计，适用于高对比的单目标场景。目标需位于ROI内；多个相离的匹配区域会合并统计，目前没有连通域筛选。内部定位测试图会随SW3切换目标明暗。

ROI、目标框和两类质心均使用**原始传感器坐标**；ROI与目标框的范围包含两端点。默认裁剪图覆盖原图x=1..318、y=1..238；映射到PGM或显示坐标时，x、y分别减1。质心按整数除法向下取整，目标中心仅在 `target.valid=true` 时有效。

以下参数在 [rtl/stream_top.sv](../rtl/stream_top.sv) 定义，修改后需重新构建bit。时间按100 MHz主时钟换算。

| 参数 | 默认值 / 作用 |
|---|---|
| `ROI_X_MIN / ROI_X_MAX` | 1 / 318，ROI横向范围 |
| `ROI_Y_MIN / ROI_Y_MAX` | 1 / 238，ROI纵向范围 |
| `TARGET_MIN_AREA / TARGET_MAX_AREA` | 16 / 37842，目标有效面积的含端点上下限 |
| `START_DELAY` | 50000000周期，即500 ms首次启动等待 |
| `FRAME_DELAY / FAST_FRAME_DELAY` | 50000000 / 0周期，普通/快速帧间等待 |
| `PREVIEW_INTERVAL` | 16，周期预览每16个成功输出包中1张图；0禁用，1每帧预览，需SW2+SW11+SW13开启 |
| `CAM_RESET_CYCLES / CAM_SETTLE_CYCLES` | 各1000000周期，即10 ms复位与10 ms稳定等待 |
| `CAM_RETRY_CYCLES` | 100000000周期，即初始化失败后等待1秒再重试；0禁用自动重试 |
| `CAPTURE_TIMEOUT_CYCLES` | 100000000周期，等待/捕获VSYNC的总超时；必须≥1 |

当前帧锁存的快速设置决定该帧结束后的等待。系统仍按“采集→FIFO读出与处理→发送”串行调度；算法使用三行缓冲，并保留外部原始帧和片上8位输出帧缓存。1 bit打包减少传输量；仅结果模式停止输出缓存读写，切回图像时重新写入完整帧。

## 接线与成像

| 摄像头信号 | Basys 3 |
|---|---|
| D0～D7 | 依次为JA1、JA2、JA3、JA4、JA7、JA8、JA9、JA10 |
| SIOC、SIOD | JC1、JC2 |
| VSYNC、WR | JC3、JC4 |
| RRST、RCK | JC7、JC8 |
| RST、HREF | JC9、JC10 |
| 3V3、GND | JC6、JC5或JC11 |
| WRST | 接同一模组VSYNC |
| OE、PWDN | 接GND |

模组必须用HREF门控FIFO写入；信号约束见 [basys3.xdc](../constraints/basys3.xdc)。

SIOC、SIOD、RST均为开漏节点。历史样机每路独立使用：3.3 V经4.7 kΩ接信号节点，节点经22 kΩ接地，节点同时接模组信号与FPGA引脚。理想空载约2.72 V；这是该样机的接线记录，不能视为稳压电源或忽略模组内部负载，最终节点实测电压未留存。更换模组时需核查电平与丝印，普通IO不能作为供电引脚。

历史清晰成像记录为镜头距纸面约24 cm、PCB距纸面约26 cm，仅代表当次搭建条件。改变距离后需重新机械调焦。详细过程见 [开发与联调日志](开发与联调日志.pdf)。

## 诊断与异常恢复

正常页LED15表示摄像头模式下的初始化或采集错误；LED14:7为frame_id低8位，LED6为心跳，LED5/4表示Sobel/测试图模式，LED3/2表示发送忙/采集忙，LED1为配置完成，LED0为复位释放。

### LED诊断页：SW14=1

LED15:8显示所选值；以下历史参考值来自原样机，供联调对照。

| 页面 | SW11:10选择 | LED15:8含义 / 历史参考 |
|---|---|---|
| SW12=0：行数 | 00 / 01 / 10 / 11 | WR窗口 / VSYNC高阶段 / VSYNC低阶段 / 0；前三项曾测得240 / 240 / 0行 |
| SW12=1：寄存器 | 00 / 01 / 10 / 11 | PID / COM10 / TSLB / COM7；曾读回0x76 / 0x02 / 0x0C / 0x00 |

行数页用SW13=0显示低字节、SW13=1显示高字节；寄存器页忽略SW13。两个诊断页中，LED6为初始化故障，LED5为采集超时，LED0为配置完成。寄存器页的LED2为读回错误，LED1为读回完成；读回错误时不能信任显示值。

### 常见现象

| 现象 | 当前行为与检查入口 |
|---|---|
| 摄像头初始化失败 | 正常页SW0=0时LED15亮；诊断页LED6亮。默认等待1秒后重新执行摄像头复位、稳定等待及完整配置，错误保持到配置成功或BTNC复位。先检查供电与SCCB接线 |
| VSYNC卡住或采集超时 | 释放WEN并丢弃该次采集，帧间等待后重试；frame_id可能跳号。内部测试图可用于检查处理和串口链路 |
| 只有JSON、没有PGM | 检查SW11与SW2；仅定位结果模式按设计不保存图像 |
| 找不到目标或目标框偏大 | 检查SW3极性、SW9:8阈值、ROI和面积范围；多个匹配区域会合并统计 |
| 串口无法打开 | 检查实际COM端口、USB连接及是否被其他程序占用 |
| 接收停在截断帧 | 默认连续1秒无字节后尝试重新同步；可调长空闲阈值或关闭空闲恢复，见下文 |

串口恢复参数示例：

```powershell
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --idle-resync 2
```

`--idle-resync`单位为秒，默认1，0表示禁用空闲恢复。阈值应大于连接可能出现的正常字节间停顿；一次0.25秒读取超时不会单独触发恢复。正常分片按完整帧长度和CRC验证；文件输入到达EOF时，会尝试恢复截断帧后面的完整包。

SW15暂停采集时，初始化重试继续进行。摄像头断电后寄存器丢失、重新插接及长期稳定性尚需实板验证；详细恢复边界见 [异常恢复记录](迭代记录_2026-10-20_异常恢复.md)。
