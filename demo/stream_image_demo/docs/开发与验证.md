## 创建可编辑的Vivado工程

需要在GUI中编辑和调试时，在新开的Vivado会话中执行：

```tcl
source {D:/你的项目目录/stream_image_demo/scripts/create_project.tcl}
```

脚本按自身路径收录当前RTL、约束和仿真文件，在项目内生成 `vivado_project/`。之后可在GUI运行综合、实现和Generate Bitstream。此路径与[快速开始](../README.md#生成当前bit并上板)中的独立构建任选其一；已有同名未保存工程时不要直接重复执行创建脚本。沿用旧工程时，确认已添加 `rtl/target_stats.sv` 及当前全部RTL。

## 运行完整回归

```powershell
python scripts/run_tests.py
```

入口会自动查找Vivado或Icarus；也可明确指定其中一个工具目录：

```powershell
python scripts/run_tests.py --vivado-bin "你的Vivado安装目录/bin"
python scripts/run_tests.py --simulator iverilog --iverilog-bin "你的Icarus安装目录/bin"
```

无仿真器时可运行 `python scripts/run_tests.py --python-only`。每次回归写入独立的 `build/regression/` 子目录，结果以其中的 `summary.json` 和日志为准；没有可用UART录制流时，Python模式会明确跳过协议交叉校验。历史bit的资源和时序报告不能作为当前RTL通过实现的证明。

## 校验交付文件

```powershell
python scripts/check_delivery.py
```

检查文件哈希、新增/缺失文件及源码汇总是否一致。审阅源码或文档修改后再更新清单：

```powershell
python scripts/check_delivery.py --refresh
```

`build/regression/`和缓存不属于交付清单。需随包保留的测试证据先放入 `evidence/`，再刷新清单。
