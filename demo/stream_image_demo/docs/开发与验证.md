## 独立视觉核心综合

新 `vision_top` 以摄像头和通用显示流为边界，在新开的 Vivado Tcl 会话执行：

```tcl
source {D:/你的项目目录/stream_image_demo/scripts/synth_vision.tcl}
```

脚本对 XC7A35T 做独立综合，默认限制为 45 个 BRAM36 等效块、72 个 DSP 和 18,000 个 LUT，超出预算会报错；结果在 `build/vision_ooc/`。该脚本没有显示引脚分配，不产生 bit，综合时序报告也不能代替最终布局布线时序。目前只通过模拟 Vivado 命令的 Tcl 语法与预算分支测试，本机未找到 Vivado，未取得真实综合结果。

## 创建可编辑的Vivado工程

以下工程和 `scripts/build.tcl` 均以原串口 `stream_top` 为顶层。需要在GUI中编辑和调试时，在新开的Vivado会话中执行：

```tcl
source {D:/你的项目目录/stream_image_demo/scripts/create_project.tcl}
```

脚本按自身路径收录当前RTL、约束和仿真文件，在项目内生成 `vivado_project/`。之后可在GUI运行综合、实现和Generate Bitstream。此路径与[串口 Demo 构建](../README.md#生成串口-demo-的-bit-并上板)中的独立构建任选其一；已有同名未保存工程时不要直接重复执行创建脚本。沿用旧工程时，确认已添加当前全部RTL。

## 运行完整回归

```powershell
python scripts/run_tests.py
```

入口会自动查找Vivado或Icarus；也可明确指定其中一个工具目录：

```powershell
python scripts/run_tests.py --vivado-bin "你的Vivado安装目录/bin"
python scripts/run_tests.py --simulator iverilog --iverilog-bin "你的Icarus安装目录/bin"
```

无仿真器时可运行 `python scripts/run_tests.py --python-only`。每次回归写入独立的 `build/regression/` 子目录，结果以其中的 `summary.json` 和日志为准；没有可用UART录制流时，Python模式会明确跳过协议交叉校验。历史bit的资源和时序报告不能作为当前RTL通过实现的证明。

当前包含 86 项 Python 测试（PC 70 项、脚本 16 项）及 20 组 RTL 仿真。`enhance_core` 和 `vision_top` 仿真后会自动调用独立整数参考模型校验导出像素。完整回归还调用实际 PC 命令行解析 7 组 FPG1 图像/定位流和 1 组 VST1 状态流。Tcl 测试在 Python 含 tkinter/Tcl 时运行，否则明确跳过；本轮环境中 3 项均已运行通过。

## 校验交付文件

```powershell
python scripts/check_delivery.py
```

检查文件哈希、新增/缺失文件及源码汇总是否一致。审阅源码或文档修改后再更新清单：

```powershell
python scripts/check_delivery.py --refresh
```

`build/regression/`和缓存不属于交付清单。需随包保留的测试证据先放入 `evidence/`，再刷新清单。
