## 下一轮的优化优先级

| 优先级 | 工作 | 依据与验收方式 |
|---|---|---|
| 1 | ROI内单目标定位，输出存在标志、面积、包围框和中心；支持亮/暗目标选择 | 当前统计固定为Y≥128，白纸场景容易统计背景。用固定与移动深色目标验收：位置跟随、无目标明确无效 |
| 2 | 分开调度目标结果与图像预览；边缘图采用1 bit打包；让帧间等待可配置 | 当前图像发送阻塞下一帧；测处理fps、预览fps及端到端延迟，检查预览是否拖慢定位结果 |
| 3 | 补摄像头完整采集、三个等待阶段的超时恢复、按钮复位与帧间模式切换联测 | 现有顶层测试只走内部图，采集测试只覆盖其中一种卡住状态。用故障注入确认能返回等待并成功获取下一帧 |
| 4 | 为参数设置边界检查，将本轮最小尺寸用例纳入默认回归，再做并行读写与更高分辨率 | 顶层图案坐标固定9位、读时钟相位计数固定8位；参数越界会静默回绕。先明确支持范围，避免仅修改W/H后卡住 |

### 性能预算

当前每帧传输 `32 + 318×238 + 2 = 75,718` 字节。1 Mbps、8N1每字节10位，仅数据在线路上的时间为 **757.18 ms**，尚未包含字节间隙。默认每轮还额外等待 **500 ms**，FIFO读出约 **76.8 ms**；Sobel的计算与读出重叠。因此先提高算法时钟对PC刷新率帮助有限。

移除固定500 ms等待，可以减少每轮固定开销，但必须保留启动等待、帧同步和错误恢复。二值输出若按连续像素每8点打包，并假设沿用34字节头尾，单帧约 `ceil(75,684/8)+34 = 9,495` 字节，线路时间约 **94.95 ms**。这只是新协议的预算，本轮尚未实现或实测该功能。

历史实现报告中LUT约4.15%、BRAM约51%，说明输出整帧缓存比算法算力更值得关注。这些资源和时序数据来自原bit对应的旧报告，修改后的RTL仍需重新综合验证。

VGA升级还需要改变缓存调度：640×480 UYVY一帧614,400字节，大于当前外部FIFO的393,216字节。应先完成定位与输出调度，再设计读写重叠和输出压缩。

## 复现与维护

在项目根目录运行：

```text
python scripts/run_tests.py --python-only
python scripts/run_tests.py --vivado-bin "你的Vivado安装目录/bin"
python scripts/run_tests.py --simulator iverilog --iverilog-bin "你的Icarus安装目录/bin"
python scripts/check_delivery.py
```

`--python-only`未发现已保存的线流时会明确跳过交叉校验；若指定 `--wire PATH`，文件缺失或解码不到要求数量的帧都会失败。完整回归会使用本轮 `tb_transport` 生成的UART字节流再验证PC接收器。

本地测试输出默认写到 `build/regression/`，不覆盖旧日志。审阅修改后，用 `python scripts/check_delivery.py --refresh` 同步源码汇总和哈希。需留档的验证输出先放入 `evidence/`。生成或下载新bit之前，核对本轮测试、时序与硬件验收范围。
