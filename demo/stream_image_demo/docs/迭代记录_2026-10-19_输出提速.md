# 输出提速迭代记录

2026-10-19第三轮，基于同日ROI定位版本。当前源码工作目录不变，交付包命名为 `demo_iterated_2026-10-19_output.zip`，之前的原始包与迭代包保留。

## 本轮完成

增加三种可切换输出：原8位图像、1 bit Sobel、仅定位结果；增加独立的普通/快速帧间等待。旧v1/v2协议及默认开关行为保留，实际启用新输出时使用FPG1 v3。新版接收器支持v1/v2/v3混合流。

打包按连续行优先、每8点一字节，最早像素放bit0，末尾高位补零。PC在CRC验证后无损展开为0/255并保存PGM。仅结果包保存目标JSON/CSV，不创建图像文件；显示时使用标注“Features only”的新空白定位画布。

## 字节数与发送预算

以下三种输出均以318×238、含定位结果为对照：

| 输出 | 图像payload字节 | 完整包字节 | 1 Mbps理想线路时间 |
|---|---:|---:|---:|
| 原始8位v2 | 75,684 | 75,758 | 757.58 ms |
| 打包Sobel v3 | 9,461 | 9,535 | 95.35 ms |
| 仅定位结果v3 | 0 | 74 | 0.74 ms |

发送器独立仿真使用 `CLKS_PER_BIT=4` 加快验证，实际从start到done测得3,106,079 / 390,936 / 3,035周期。打包相对原始图的发送阶段约快7.95倍；仅结果相对原图的线上数据量约小1024倍。原始与打包均核对全部像素、末位填充和CRC，仅结果确认不进入RAM读取状态。

上述是线路预算与仿真发送阶段对比。默认板上波特率仍为1 Mbps；整机还需采集、VSYNC同步、FIFO读出、算法完成及可能的帧间等待，不能把发送阶段提速倍数当作整机fps提升倍数。

## 使用方法

需要以当前全部RTL重新构建bit，并使用当前PC接收器。在正常显示页 `SW14=0` 时：

| 控制 | 效果 |
|---|---|
| SW10=1、SW1=1 | Sobel 1 bit打包，可选是否打开SW2定位 |
| SW11=1、SW2=1 | 仅定位结果，优先于打包 |
| SW12=1 | 使用快速帧间等待；默认0周期 |
| SW10/11/12=0 | 原图像格式与默认500 ms帧间等待 |

灰度模式会忽略打包请求；SW2关闭时会忽略仅结果请求。SW14=1时SW10/11/12只用于原诊断页，三种提速请求均视为关闭。SW0内部图/摄像头、SW1灰度/Sobel、SW2定位和SW3目标明暗等功能沿用上一轮。

`START_DELAY`专门保留首次启动等待；后续普通/快速等待使用新增顶层参数 `FRAME_DELAY` / `FAST_FRAME_DELAY`，默认分别等于START_DELAY和0。控制在帧间锁存，当前帧所选速度决定该帧之后的等待。按钮复位会重新执行首次等待和相机初始化。

仅结果模式关闭输出缓存的读写使能；切回图像模式时完整写入下一帧后才发送。8位缓存保留以支持运行时切换，1 bit打包只降低传输量，不代表片上存储减少8倍。采集与发送仍按帧串行调度。

## PC输出与协议

v3仍为72字节头；byte70的transport_flags为1（打包无定位）、5（打包含定位）、6（仅结果），byte71为0。payload_length记录实际线上字节数，目标字段继承v2约束。无定位打包时目标扩展必须全0。字节布局和优先级详见 `输出协议_FPG1v3.md`。

JSON/CSV新增pixel_format：gray8、mono1、none。仅结果的pixels为空、image_file为null；CSV继续保留面积、坐标和、有效性和目标中心。旧CSV保持原样，新schema另写metadata_v3.csv。PGM始终存展开后的8位图，目录中的JSON数量可以多于PGM数量。

## 验证结果

- Python接收器34项、测试入口12项，共46项通过。
- 默认RTL回归扩展到13组，保留全部旧图像、采集、定位与UART测试，并新增output_transport、output_budget、top_output。
- 独立发送器固定6帧覆盖打包无/有定位、有效/无目标仅结果、灰度请求回退、回到v2图像；旧v1/v2测试继续通过。
- 预算测试覆盖1像素、8像素边界和默认QVGA，核对所有像素、包长、CRC与发送周期。
- 顶层5帧覆盖旧图、打包定位、仅结果、恢复原图及诊断页屏蔽新模式，检查帧中切换不改变当前包。
- 首次17周期、普通29周期、快速3周期及额外快速0周期验证通过。仅结果期间输出缓存和read_data保持，恢复时逐地址重写与逐像素校验通过。
- 故意移除实际RAM写/读门控后，独立快照回归都能检测到错误，确认测试覆盖实际缓存行为。

最终完整回归、5组UART字节流到PC解码的结果及测试数量以 `交付核验.json` 为准。证据放在 `evidence/regression_20261019_output/`，含output_budget.json、原始线流、解码JSON/CSV/PGM和零等待/门控反证日志。

本轮没有Vivado综合、布局布线、新bit生成或上板。原预编译bit与资源/时序报告仍属于最早硬件基线；当前输出模式的实际帧率、串口长期稳定性和资源时序需实板与实现验证。
