# 异常恢复迭代记录

2026-10-20完成第四轮，基于2026-10-19输出提速版本。交付包为 `demo_iterated_2026-10-20_recovery.zip`，之前各版压缩包保留。当前功能与测试范围以本记录及根目录 `交付核验.json` 为准。

## 摄像头初始化恢复

此前，摄像头寄存器写入遇到一次NACK后，配置模块会永久停在FAILED，必须按BTNC才能重新尝试。顶层还用尚未更新的pattern_mode控制错误灯，导致第一次配置失败时普通页可能没有错误提示。

现在配置模块先锁存应答失败，完成当前事务的STOP并释放SIOC/SIOD，再对外发布error。顶层等待 `CAM_RETRY_CYCLES` 后重新执行物理RST、稳定等待、全部39笔寄存器配置及诊断读回。默认100000000周期，在100 MHz下为1秒；设0禁用自动初始化重试。重试间隔从上一次配置失败发布后计算，整个重试周期还包含复位、稳定等待与配置时间。

初始化错误锁存为camera_fault，在自动重试期间保持，配置成功或BTNC复位后清除。普通页SW0=0时LED15显示初始化/采集错误；两种诊断页均用LED6显示初始化错误。内部测试图与初始化恢复独立运行。诊断读回的read_error不会触发重配，避免因读回异常重置已运行的摄像头。

新增 `CAPTURE_TIMEOUT_CYCLES` 将现有采集超时配置暴露到顶层，默认100000000且必须≥1。VSYNC在等待消隐、等待有效帧或捕获帧任一阶段卡住时，都释放WEN并丢弃该次采集。后续按帧间等待重新发起；该路径保留已有逻辑，本轮补齐恢复回归。超时尝试占用frame_id，因此收到的序号可以跳号；不会把旧缓存作为成功的新帧补发。

SW15仅暂停后续采集，当前帧正常完成，初始化重试继续进行。初始化失败重试与VSYNC恢复均不改变已有v1/v2/v3输出格式。

## 接收分片修复

此前，未收完整的图像帧中若恰好出现另一个CRC正确的完整FPG1包，接收器会提前丢弃外层帧。相同字节流一次传入可得到正确图像，换一种串口分片方式却得到内嵌伪帧。这是二进制图像数据合法包含任意字节时的实际歧义。

现在正常feed保留未完成的外层候选，等到声明长度满足后检查CRC，失败才重新扫描。分片位置不会改变合法完整帧的结果。仍允许在明确边界恢复截断帧后面的完整包：

- 文件输入到达EOF时，先扫描并保存残留数据中的完整有效包，再检查是否仍有未完成尾帧。
- 串口输入连续无字节达到 `--idle-resync` 指定秒数后，才执行一次边界恢复。默认1.0秒；0禁用空闲恢复；负数、NaN和无穷大不接受。计时使用单调时钟，每次收到字节重新计时。
- 单次串口read超时仍为0.25秒，短暂超时不会独立触发边界恢复。

空闲恢复明确把等待超过阈值的未完成外层视为已中断；阈值应大于实际连接可能出现的正常字节间停顿。需要完全按长度/CRC等待的场景可设 `--idle-resync 0`，其代价是损坏长度后要等更多字节或文件EOF才恢复。API的明确恢复边界也应遵守这一约定，不应在任意网络/串口分片后调用。

已有metadata.csv若是UTF-16、损坏编码或不兼容表头，接收器保留该文件并选择metadata_v3.csv或后续编号，不再因读取旧CSV而中断采集。

预览窗口在串口暂时没有输出帧时仍处理键盘事件，可按q退出。测试入口也修复了Windows旧编码控制台无法显示特殊诊断字符时的异常：保留完整UTF-8日志，控制台以转义显示无法编码的字符，并正确将summary记录为failed。

## 验证与边界

最终完整回归通过：接收器43项、测试入口13项，共56项Python测试；15组RTL；6组原始UART协议交叉解码，共26个有效包、26个JSON、23张PGM，无拒绝包。仅定位结果的3个包没有PGM，符合协议。完整记录位于 `evidence/regression_20261020_recovery/full/`。

新增camera_retry与top_recovery回归，默认RTL回归共15组。camera_retry覆盖禁用重试、1周期最短重试、总线已释放、错误灯跨重试保持和手动复位。fifo_capture扩展为三个阶段超时后恢复，以及读到第5像素时复位后重新对齐；共6个完整帧、1个丢弃的部分帧。camera_config验证每次完整39笔事务、NACK完成STOP后发布错误及复位后重配。

顶层恢复测试使用实际SCCB从设备模型、FIFO字节模型及UART接收，覆盖摄像头NACK时内部图仍输出、无按钮恢复配置、两次VSYNC超时均不发送旧图、恢复后完整真实源图像、暂停和恢复后新图。导出3个完整协议包，供PC交叉解码。

该用例完成27次NACK后的物理复位重试，每次间隔精确31周期，复位5周期、稳定等待7周期；恢复后完成39笔配置写入。最终包序号为1、4、5，2和3对应被丢弃的超时尝试。测试均采用缩短时序参数，不能视为实板时间测量。

负向对照将原先提前发布配置错误及超时不关闭WEN的行为放入独立测试副本，增强回归均准确报错。接收端对照使用旧版代码复现分片误判，新版检查完整外层包在不同切分下保持一致。详细测试数量、原始日志和协议文件记录于 `交付核验.json` 及 `evidence/regression_20261020_recovery/`。

本轮使用Icarus仿真和Python自动测试，未连接真实串口或显示窗口，未进行Vivado综合、实现、新bit生成或上板。原 `build/vivado/stream_top.bit` 保持历史基线；使用当前RTL恢复功能需要重新构建。摄像头断电后寄存器丢失、重新插接、时钟故障及长期稳定性仍需实板验证，本轮不据此声称已经覆盖所有硬件断连情形。

## 复现

```text
python scripts/run_tests.py --python-only
python scripts/run_tests.py --simulator iverilog --iverilog-bin "你的Icarus安装目录/bin"
python pc/receiver.py --input evidence/regression_20261020_recovery/full/verify_top_recovery/top_recovery_wire.bin --count 3 --out replay_recovery
python pc/receiver.py --port COM10 --baud 1000000 --idle-resync 1 --out received_frames
python scripts/check_delivery.py
```

COM10仅为示例，按实际设备修改。正常控制、1 bit输出和仅定位结果等功能继续参见README与v2/v3协议文档。
