# 周期预览与接收延迟迭代

2026-10-22完成。基于异常恢复版本，增加高速定位时的周期图像预览，并补齐上次中断后未完成的测试入口。

## 功能

正常页打开SW2、SW11、SW13，可在仅定位结果流中插入图像。`PREVIEW_INTERVAL=16`时先发图像，随后15个结果包，再发图像；0禁用、1每帧图像。SW12仍控制快速帧间等待。Sobel预览可通过SW10打包为mono1，灰度预览采用v2原始图，结果采用v3，未修改协议格式。

计数在tx_done后推进，暂停或失败采集不消耗配额。重新启用预览、采集源变化、图像模式或Sobel阈值变化，以及内部图明暗极性变化时，重新从图像开始。全部实际输出设置在帧边界锁存，诊断页屏蔽周期预览请求。

接收器新增`--display --hold-preview`，用最近一张真实图作为显示背景，在其上绘制当前目标。两行标签分别标注历史图像和当前定位帧号；缓存只保存未叠加的像素。尺寸、模式、阈值变化或非递增帧号会清缓存。仅结果包仍不保存PGM，JSON/CSV也不引用旧图。协议没有源或会话标志，不能识别所有漏包后的源切换；历史图与当前定位不是同时采集。

串口接收改成先等1字节，再读取已经到达的数据，总量最多4096字节。短74字节结果包不再因read(4096)而等待0.25秒；无数据时仍使用原读取超时。此处说明代码和模拟验证的行为，不代表真实串口延迟测量。

## 验证

完整回归通过50项接收器测试、13项测试入口检查、16组RTL仿真与7组原始串口数据交叉解码，共39个JSON、31张PGM。

新增top_preview同时运行间隔0、1、3的三个顶层实例，每个检查13个包。独立计算图像像素、目标面积/坐标和/边框、亮像素统计及CRC，检查暂停、重新进入、诊断屏蔽、模式/阈值/内部图极性切换，以及仅结果帧的RAM读写门控。间隔3的13包录制流由PC再次解码，得到8张PGM和13个JSON。

摄像头超时和恢复沿用并重跑现有top_recovery外部SCCB/FIFO模型测试。新增周期预览测试采用内部图，未覆盖周期预览与真实摄像头断连组合的全部情形。默认16周期使用同一计数实现，新增顶层测试缩短为3以验证多轮调度；没有实测默认16周期的板端帧率。

原始日志、录制流、解码输出与summary.json保留在[回归证据](../evidence/regression_20261022_preview/)，范围汇总见[交付核验](../交付核验.json)。未运行Vivado综合、布局布线、新bit生成、实板串口或真实GUI窗口，随包历史bit与当前RTL不匹配。

## 使用

将开关SW2、SW11、SW12、SW13置1，其余置0，即摄像头快速定位加灰度周期预览；增加SW0可用内部测试图。构建当前RTL后运行：

```powershell
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --display --hold-preview
```

COM10按实际端口修改，显示需要可选opencv-python。离线回放只需Python标准库，在项目根目录执行：

```powershell
python pc/receiver.py --input evidence/regression_20261022_preview/full/verify_top_preview/top_preview_wire.bin --out build/regression/preview_replay --count 13
```
