# 持续接收、断线重连与原始数据录制

2026-10-22完成，基于`b262f8d`周期预览版本。本轮修改PC接收器，RTL、约束及协议格式保持上一版本。

## 行为变化

此前串口暂时不可用或USB断开会直接抛出异常，不能保留连接边界，也没有原始接收字节可用于复查。现在可用`--reconnect SECONDS`启用自动重连，默认0关闭；初次打不开端口和运行中读出失败都按指定间隔重试同一个端口。等待拆为不超过0.25秒的轮询，显示窗口仍能处理q，Ctrl+C也能退出。端口编号变化需修改`--port`。

确认连接失败时，将旧连接视为流边界：恢复缓冲中完整、CRC正确的包，丢弃残余半帧，清空旧预览并显示断线状态。新连接不会与旧半帧拼接，即使`--idle-resync 0`也会隔离；`--count`按整个采集过程累计。

`--record-wire PATH`将每次成功读取的原始字节写入排他创建的二进制文件，包含噪声、坏包和半帧。后续成功连接另开带编号的文件，保留独立流边界；已存在的编号跳过，已存在的首文件拒绝启动。首字节在查询后续可读字节前就写入，因此随后发生读出错误时，该字节仍留在录制中。文件缓冲在每次读取后刷新。

录制失败与串口失败分开处理，磁盘写满、无权限创建新段或保存图像失败会报错退出，不会触发无意义的重连。默认不重连时，端口I/O失败会返回非零状态和清楚的错误，已保存数据保留。

## 验证

接收器64项、测试入口13项，共77项Python测试通过。新增14项测试覆盖：初始端口不可用、运行中断线、半帧隔离、尾部完整包恢复、预览清空、等待时退出、Ctrl+C刷新文件、首字节后的断线、既有文件保护、磁盘写入/切段/保存失败、参数校验，以及32次连续重连时重复frame_id的文件与CSV保留。

7组此前由实际RTL仿真导出的UART流均由新版接收器重新解码，累计39个有效包和31张PGM。没有重新运行RTL仿真，因为本轮未修改RTL；16组RTL通过记录保存在[上一版核验](history/交付核验_2026-10-22_preview.json)。

另外，将周期预览UART录制流拆为两个模拟连接：首连接收到帧1、2、3以及帧4的45字节前缀后断开，新连接从帧5继续。真实CLI接收循环最终保存12个JSON与7张PGM，序号为1、2、3、5至13，两个原始文件逐字节保持输入。该例只模拟串口连接，图像和目标统计字节来自已有RTL仿真，不是新实板数据。

日志、分段原始流、回放结果和模拟重连样例保留在[验证证据](../evidence/regression_20261022_serial_sessions/)，范围汇总见[交付核验](../交付核验.json)。没有进行实物USB拔插、驱动兼容性、真实显示窗口或长时间硬件测试；录制只能保存操作系统已交付的字节。

## 使用

在项目根目录执行，按实际情况替换COM10，并为每次采集选择新的录制首文件路径：

```powershell
python pc/receiver.py --port COM10 --baud 1000000 --out received_frames --reconnect 1 --record-wire recordings/session.bin
```

需要显示时增加`--display --hold-preview`。分段文件分别通过已有`--input`回放，详见[操作手册](使用手册.md#持续接收断线重连与原始录制)。本轮PC功能无需修改板端协议；当前功能所需bit仍应由当前RTL构建，随仓库历史bit不能作为新RTL实现证明。
