# 扩展路线与评价设计

当前版本已建立独立板端运行、三模式显示、实际ROI反馈和逐项整数参考核验。下一轮可沿现有模块边界开展改进，每一项都对应清晰的输入、结果和资源代价。

| 任务 | 工作位置 | 验证方法 |
|---|---|---|
| 前缀与边框候选筛选 | `plate_region_locator`、`char_segmenter` | 保存原始ROI和候选框，分别统计汉字残留、边框误检、真字符误删及整串精确匹配 |
| 位置与尺寸覆盖 | 定位与分割前端 | 按未参与调参的牌号、水平/垂直位置、大小、照度分组测量定位成功与切分质量 |
| 稳定结果展示 | 结果事件与OSD | 先统计logit间隔与错误关系，再比较拒识或跨帧投票的精度、延迟和更新频率 |
| 进一步压缩存储 | mask/洪泛队列、CNN RAM、调试快照 | 在相同输入上保持数值输出一致，比较BRAM、LUT、周期与时序 |
| 图像呈现质量 | 相机与LCD接口 | 对照照明、曝光、线缆和扫描同步条件，保存数字流与实际画面记录 |
| 扩展字符集 | 模型、协议、字库 | 建立独立字符来源与真实场景测试，评估分割可用率及整串结果 |

独立评估集按真实牌号或字符来源划分，开发集用于规则与模型选择，保留集用于最后评分。指标分别报告定位漏检、字符切分、分类、整串精确匹配和拒识，并保存场景条件、原始小图、真实文本及版本身份。

历史数据用于复现既有行为；新的评估应记录新增来源和分组，避免把反复使用的同一场景计作新泛化样本。当前问题的具体事实与处理状态统一保留在[验证数据](validation_data.md)和[异常台账](anomaly_register.md)。
