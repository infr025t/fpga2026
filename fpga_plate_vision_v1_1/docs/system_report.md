# 基于 FPGA 的独立车牌视觉系统：工程报告

## 设计目标与成果

本项目面向Basys 3上的相机视频处理与英数字车牌识别，将采集、计算、识别和显示组织成一条可独立运行、可逐级核验的硬件链路。系统从OV7670 FIFO模块取得灰度视频，在LCD上提供RAW、EDGE和OCR三种模式。OCR模式在FPGA内完成目标定位、字符分割、归一化和量化CNN推理，并将识别文本及实际定位区域叠加到原灰度画面。

工程的主要价值体现在三方面。第一，视频前端使用行缓存完成Gaussian3与Sobel3运算，按有效像素连续推进，显示与识别具有独立调度。第二，识别使用一幅160×120灰度小图，把帧存储、端口所有权和逐字符计算统一到明确的控制流程。第三，旁路观察协议将原图、字符框、归一化像素和分类分数保存为证据，能够与PC整数参考逐项复算。系统运行、数学实现和结果呈现因此形成完整验证链。

v1.1 增加白字选择，使蓝底白字牌面能够复用现有字符分割、灰度归一化和冻结CNN。SW5选择字符极性，原始画面与定位继续使用原灰度，三模式显示和绿色ROI反馈保持原有组织方式。当前实机连续20次均输出AL67L8，120字符的92,160像素与4,320分数全部与整数参考一致，改动机制与场景条件见[白字支持](reference/white_character_support.md)，新版本的实现和板测状态见[当前验证](reference/current_validation.md)。

v1.1在100 MHz下WNS +0.175 ns、WHS +0.017 ns，顶层15,612 LUT、18,901 FF、44.5块BRAM36等效和9个DSP。白字功能相对v1.0增加19 LUT和6 FF，未增加BRAM与DSP；独立ROI显示模块仍为64 LUT、62 FF。

## 系统工作过程

相机采集端负责初始化、FIFO读写协调及有效像素输出，顶层在显示端可接纳整帧时发起一次源帧读取。视频适配器根据锁存模式选择原灰度旁路或边缘链。RAW输出640×480像素，EDGE按当前接口裁边输出630×470像素。LCD接收端使用64字节队列衔接像素与8080总线，将灰度映射为RGB565并写入显示窗口。

OCR分支直接取得原灰度源，每4×4采样步长保留一个像素，形成160×120小图。控制器完成整帧完整性检查后，依次运行原灰度几何定位、按所选字符极性执行的局部阈值与连通域分割、候选排序与粘连拆分，再对每个字符执行32×24灰度归一化和36类整数CNN。整串结果通过事件接口发给显示与观察支路。计算忙时控制器保留当前小图，下一源帧可继续用于视频，待任务释放后再接纳新的识别帧。

显示端保存最近的完整文本和有效ROI，在新显示帧边界提交。文字和框坐标各自在一帧内保持稳定；ROI由分割事件更新，文字由完整结果事件更新，两者不保证属于同一捕获帧。ROI使用分割实际采用的半开区间，将小图坐标乘4映射到640×480画面，绘制绿色2像素边框；LCD的水平居中偏移由窗口驱动统一处理。定位失效、非法区域或采集中止会撤销待显示框，退出OCR后清除旧结果。绿色表示当前几何区域，识别正确性由数据评分决定。

## 图像与识别计算

Gaussian使用3×3二项式核，权重和为16，整数累加后加8右移4位。Sobel对平滑结果计算水平及垂直梯度，以绝对值之和作为幅值，再按阈值产生边缘。两级邻域通过行RAM与有效标志流水连接，输入气泡不改变像素顺序；帧中止清除有效状态。当前EDGE的每边5像素裁剪是既定接口行为，具体坐标和边界推导见[算法原理](reference/algorithm_principles.md)。

识别前端利用小图灰度和几何约束寻找近水平亮底区域，分割后通过候选尺寸、位置与排序形成字符序列。粘连拆分在过宽连通域的列投影中寻找稀疏切口，检查拆分后的子框是否符合字符条件；无法形成合格子框时保留原域。归一化读取小图灰度，并应用与分割相同的极性标志，保留字符内部笔画灰度信息。白字模式以255减去读取值，再使用既有统计与缩放步骤，生成CNN需要的亮笔画、暗背景表示；权重和分类计算保持不变。

CNN输入形状为1×32×24，包含8通道3×3卷积、2×2最大池化、16通道3×3卷积、第二次池化及36类全连接。卷积权重为int8，激活为uint8，累加和分数为int32；输出按有符号argmax取类别。每字符算法计算量304,128 MAC，实测核心942,444周期，即9.42444 ms。二者分别描述算法乘加数与实际硬件排程时间。

模型输出字符顺序为`0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ`，冻结binary为29,128字节。板端推理无需重新训练。模型数据、量化尺度、字节布局及合成字符测试结果详见[模型与训练](reference/model_and_training.md)。前缀排除属于位置规则，模型本身为36类英数字分类器。

## 证据如何支持工程成果

验证从独立模块逐步覆盖系统接口。控制仿真检查模式变化与任务所有权；自主整链使用真实定位、分割、归一化和CNN；显示仿真在LCD实际写事务重建像素；布局布线提供当前冻结源对应的时序与资源；板端观察器记录实际硬件输出，并由PC数学参考复算。每一层承担明确验证职责，原始输入和版本身份一并保留。

v1.1白字完整链仿真输出AL67L8，六个字符的4,608个归一化像素与216个有符号分数全部符合整数参考，并通过空白帧撤框检查；原暗字链回归输出BD12345，5,376个像素与252个分数全部一致。配合极性切换控制检查与61项PC测试，这组证据验证了最小改动的帧级行为及数值一致性，见[仿真汇总](../evidence/blue_polarity/simulation_summary.json)。

当前蓝牌板测的源帧起始节拍约22.51 fps、OCR结果约5.63 fps，采集开始至结果平均153.06 ms。数据来自100 MHz FPGA时间戳。视频持续推进，识别按实际候选数执行逐字符串行计算；旧版不同候选数的统计作为历史对照保留在数据页。

识别效果单独按真值统计。历史对齐BD12345场景有连续100次整串正确记录；v1.0的K38817场景保留了前缀候选问题，绿色框版本10次整串均多一个前导字符，前版100次均多两个前导字符。逐像素、逐分数一致说明硬件执行与参考一致，当前前缀现象来自前端候选范围和版式规则，详细输出、分母与失败区域在[验证数据](reference/validation_data.md)集中给出。完整异常处理过程见[异常台账](reference/anomaly_register.md)。

## 工程组织与交付

交付采用四个并列目录：`project/`提供可维护源码与执行入口，`docs/`提供原理和工程报告，`release/`提供确认版本BIT及LTX，`evidence/`保留冻结源、原始板测、工具报告和历史依据。RTL按顶层、驱动、视频、识别、调试和公共单元分层，共40个模块；PC工具按协议解析、采集、组帧和数学核验分工。模块边界以时序接口和数据所有权确定，使后续改进能够定位到具体工作单元。

正常使用由实体开关选择三模式：SW4=1进入OCR；SW4=0时SW3选择EDGE/RAW。SW5=0选择暗字、SW5=1选择白字，仅作用于自主OCR；切换后中止旧任务并清除旧显示结果，下一接纳帧锁存新的选择。本版已写入QSPI Flash，并通过重新加载与视频运行检查；JP1保持QSPI用于上电自启动。完整接线、模式优先级、启动和恢复控制步骤见[接口与操作](reference/interfaces_and_operation.md)，重新构建及离线验证入口见[工程与复现](reference/engineering_and_reproduction.md)。

本版本交付了从相机输入到LCD反馈的完整FPGA视觉系统，以明确的流式接口、小图任务调度和整数参考验证保持各模块可组合、可追溯。绿色实际ROI反馈使识别区域直接可见，白字选择进一步统一两种字符极性的处理入口；同图证据、帧级控制与整数参考共同支持后续场景评估。
