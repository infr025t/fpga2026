# 识别结果角落显示（独立测试工程）

## 使用与含义

自主识别模式（SW12=0、SW13=0）下，视频左上角显示黑底白字的最近一次完整结果。SW2切换RAW/EDGE不改变识别输入。无需PC参与计算或向板卡发送命令。

- `WAIT`：等待启用后的第一次完整结果。
- `NONE`：本次分割没有字符。
- `ERR`：本次任务报告采集/分割/计算错误；不继续把旧答案显示为新结果。
- `OFF`：人工回放或相邻字节诊断模式，自动识别关闭。
- 正常结果：显示前8个字母数字，超过8个时第9格显示`+`。这只是显示长度限制；分割与串口仍保留原有最多64字符能力。

相机画面内坐标 `(8,8)` 起，字框144×16像素；字体5×7点阵放大2倍，每字符槽16×16。RAW显示在800×480屏幕的 `(88,8)` 起；EDGE因既有裁边窗口，起点为 `(93,13)`。字框覆盖该小块视频，不占用额外整帧缓存。

识别完成时锁存结果，在下一次被接纳的视频帧边界统一提交。若结果和帧开始同拍，到再下一帧显示；不会在同一帧绘制一半新字、一半旧字。显示的是最近完成的识别结果，不承诺它来自当前正在显示的视频帧。暂停视频后文字也暂停刷新。

## 实现边界

`plate_recognition_subsystem`仅新增完整结果输出端口；`plate_text_overlay`保存最新/当前文字并生成字模；`video_lcd_sink`在队列出口将文字像素替换后交给原8080总线。识别算法、模型、相机读取、LCD初始化与总线时序均保持原实现。没有新增反压路径或整帧RAM。

显示队列的`input_crc/output_crc`继续比较未叠字的原像素，用于验证队列传输一致性；它们不再代表最终叠字后的屏幕像素CRC。最终屏幕像素由LCD引脚级仿真单独检查。原UART图像和参考模型也不含叠字。

## 验证

- 独立模块仿真：整帧原子更新、同拍事件、短文字清理、空结果、错误、关闭/重新开启、超长标记、边界裁剪及复位均通过。见 `reports/text_overlay_rtl/green.log`。
- 完整LCD链仿真：从WR上升沿重建16位总线字，逐项比较640×480 RAW及630×470 EDGE的603,300个RGB565像素；包含源端空拍、模式切换清屏、帧中结果更新和队列CRC检查。见 `reports/lcd_text_rtl/green.log`。
- `reports/lcd_text_rtl/lcd_bus_preview.png`由仿真实际输出总线重建，属于仿真证据，不是实物屏幕照片。

## 构建与实机结果

- `build_osd/autonomous_board.bit` 已下载至Basys 3配置RAM；用户确认屏幕能看到文字，位置与大小合适。实体开关仍直接控制板卡，未启用VIO覆盖。
- 布局布线：WNS +0.104 ns、WHS +0.025 ns，TNS/THS=0；14,740 LUT、18,340 FF、40 RAMB36+9 RAMB18、9 DSP。比上一构建增加280 LUT、142 FF，BRAM/DSP不变。见 `build_osd/timing.rpt`、`build_osd/utilization.rpt`。
- 实拍20次任务：20/20与参考模型一致，共35字符、26,880归一化像素、1,260分数，差异均为0；bad_captures和publisher_dropped均为0，源帧start约22.50775帧/s。
- 本轮实拍牌面先后明显下移，超出原固定ROI；结果为5次`DM1O1AC`、15次空结果，与BD12345真值相符为0/20。这个数字明确记录为定位区域不适配条件下的识别失败，不能将数值一致性写成识别准确率通过。叠字显示的是硬件真实结果，没有用真值替换结果。见 `reports/osd_board_20/summary.json`、`reports/osd_board_20/metrics.json`及该目录首末帧的 `preview.png`。
- 识别算法、模型、相机读取、LCD初始化和总线RTL的哈希与上一验收构建一致。新增源文件和BIT清单见 `reports/osd_artifacts.json`。

本功能仅在测试工程迭代，Flash及正式仓库未修改。断电重启仍会载入原Flash程序，不含本次识别叠字；重新下载本测试BIT可恢复。
