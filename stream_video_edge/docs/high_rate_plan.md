# VGA20fps以上：预想与当前逻辑的兼容性（本轮不执行）
## 目标和证据边界
RAW是原始Y灰度，640×480；EDGE为原输入每边裁5像素的630×470二值图，放回对应屏幕位置。目标是连续独立显示RAW≥20fps，不能以核心吞吐或读取峰值代替屏幕实际帧率。本轮只接回核心，读取仍2MHz，不修改传感器时钟、LCD时序或引脚驱动。
用户更正：本轮改善对应全部摄像头线缩短约一半，不是只缩短RCK。后续洞洞板全组线≤10cm。原单RCK归因已在测试记录追加更正。
## 吞吐预算
- 摄像头UYVY每帧614400B，20fps有效数据12.288MB/s；计入消隐与调度必须留余量。当前从HREF测得行1280B/426.7us≈3MB/s，甚至有效行本身也不支持20fps，不能只提高读钟。
- FPGA仅处理Y：20fps为6.144Mpixel/s；原100MHz核心每有效拍一像素，其结构可复用，需重新验证输入间歇、跨域和资源时序。
- LCD八位RGB565每像素两字节，同样至少12.288MB/s，要求平均每像素≤162.8ns。只更新640×480窗口，左右黑边初始化一次，不重复刷整屏800×480。
- 当前总线4/5/3/2拍，每16位字至少27个100MHz周期，忽略上层等待也仅约3.70Mpixel/s（12.1fps上限），当前时序不能达到20fps。用户提供NT35510手册363页给出写周期≥33ns、WR高/低≥15ns、数据建立≥15ns/保持≥10ns；未来可据此设计约50~70ns/字节的保守优化，再实物验证，不能直接按芯片理论极限使用。
- 去除帧尾固定100ms间隔，以及逐帧重新等待预备行/下一场的额外空场；从连续场中有序选择要显示的完整帧。

## 当前每项逻辑如何处理
| 当前机制 | 高速兼容性/计划 |
|---|---|
| 独立WRST和RRST，首字节预取计数、UYVY取Y | 保留协议语义；同步复位的建立保持按新RCLK/WCK重新计算；不能每20行重新RRST |
| 两级同步、VSYNC双向资格判定、HREF计数滤波 | 保留；以时间定义并核对最短真实脉宽，不盲目沿用64拍/128拍 |
| 32行起读、按完整行发放credit、129字节保护、溢出保护 | 按实测写入速率、行长、读时钟及队列余量重新推导；保护条件保留，阈值不是永久常数 |
| 慢读尾部补写两行、FLUSH_GUARD | 这是现有低速提交尾部的处理，不能简单删去。先明确AL422流水提交和读写间隔；高速重新设计帧尾收尾，保证最后像素合法、下一帧不混入。预备写复位同样在安全空白窗口完成 |
| 非采集阶段RRST低、RCLK持续运行 | 保留其“无所有权时不任意推进读指针”的目的；具体高速时钟与刷新需重新满足手册 |
| 当前下降沿单次采样和2MHz约束 | 不能沿用到40MHz。40MHz半周期12.5ns，AL422 tAC最大15ns尚未计连线和FPGA输入延迟；需新时钟/采样相位与输入约束，不增加提前比较或图像修补 |
| 固定100MHz核心、高斯平滑与Sobel | 不更改算法；跨域数据在核心入口排队，元数据随像素传递；核心运行后不受LCD反压 |
| 显示侧64像素队列 | 高峰读取与较慢LCD不匹配。按一次突发及在途流水量预算BRAM队列，预留空间后才启动读取 |
| UART/快照/JTAG | 测试诊断不参与正常视频流速率，不用串口承载20fps、不靠PC做计算 |

## 读钟与突发：不能直接承诺40MHz
100MHz整数分频不能生成均匀40MHz（周期2.5拍）；需要MMCM/PLL及新的读入时序或更高基准时钟。单独改变PERIOD不是40MHz方案。

40MHz读UYVY会产生20Mpixel/s的Y突发，远高于20fps的6.144Mpixel/s平均输出。20行UYVY=25600B，40MHz读取约0.64ms，产生12800B的Y；显示同时消化一部分，但64B队列明显不够。10~20行或8~16KiB级显示队列是可预算的方案，不等于必须新增整帧缓存；精确大小按净峰值、调度间隔和流水排空量计算，不能凭经验冻结。

更关键：模块没有单独引出/RE，不能把/OE当读使能。AL422手册8.3.1建议读写时钟至少1MHz，且二者中较快的时钟必须持续运行以刷新DRAM；若40MHz RCLK比WCK快，简单停RCLK等待显示存在协议冲突。原低速行credit暂停不能不加判断地照搬。传感器配置连续PCLK，不等于已实测模块WCK的全部波形。

优先预想：先将传感器和LCD调到有余量的20fps链路，再选择足够且有时序裕量的约16~20MHz读速，而非为峰值追求40MHz；20MHz有效读上限10Mpixel/s，平均吞吐有空间，能否达到还取决于消隐与调度。若仍要40MHz突发，必须解决无/RE时的暂停/刷新条件，并验证完整的读时序和队列预算。两者都是后续方案，当前没有上板验证。

## 必须区分单张模式与连续视频
当前是“每次采集都预备写复位、等待下一完整场、必要时借下一场追加提交尾部、结束后RRST低”的单张状态机。不能简单删除100ms间隔就称为连续视频。反复预备和等待可能跳过场，即使每场读取很快也会限制实际帧率。

更合理的后续候选是：启动/异常重同步时才统一初始化FIFO指针，正常视频阶段按连续字节流维持读写序列、帧边界和绝对行计数，在场边界重置图像坐标而不是每场都重置FIFO读写指针。保留独立WRST控制和首字节语义，重新验证跨环绕、FIFO提交延迟及完整帧归属。下一场写入可提交上一场尾部，不必每帧停止后再专门追加两行。当前FINISH拉低RRST也应仅用于退出采集/恢复，不可在连续流的每个场边界照搬。这个控制层调整与算法核心独立，属于计划内后续设计，本轮不实操。

若LCD扫描与GRAM写入异步，正确像素也可能在运动时形成刷新交界。FIFO字节错位/浮雕与这种显示撕裂需要分开诊断；若要求严格无撕裂，需要核实TE等同步条件，而当前接口尚未使用TE。不能把源/显示入口CRC一致宣称为屏幕扫描每一瞬间都无撕裂。

AEC/AGC继续保留。未来20fps验收需统计光照变化下实际帧周期和最大曝光；如自动控制延长场周期，应明确照度/曝光上限，不能只报告明亮静态环境的峰值。

收敛前测试版含153600B双通道抽样快照和JTAG，BRAM36等效50/50已用满。V0.4默认构建已移除大快照，保留为可选诊断；最终资源以reports/lcd/implementation/utilization.rpt为准。释放的存储可用于后续行级队列，但目前没有实施高速队列或高速读取。

## 洞洞板与10cm线
10cm以内是合理布线目标，不是稳定性的保证阈值，也没有证据说40MHz必须小于某个厘米数。高频缩小采样窗口；线长、回流路径、分支、相邻串扰、连接器和边沿共同决定可靠性。
- 相机时钟与控制避免面包板和分支，短直连；数据线长度尽量接近，避免绕远路、长并行悬空。
- 提供短且充分的地回流，相机附近确认去耦；时钟旁有地比单纯规定10cm更有意义。
- 可在FPGA时钟驱动端预留串联电阻位置，阻值以电气和实测决定，不无依据同时改变驱动强度、阻值和频率。
- LCD WR与数据线同样纳入高速布线。固定洞洞板后，保持同一程序做固定图案CRC及实拍动态基线，再提高频率。
- 若10cm方案仍不稳定，可能需要更短线/更好的回流或连接形式；不能用图像修补、跳坏帧掩盖。

## 后续顺序
1. 当前2MHz下接回核心，高斯EDGE连拍和屏幕实物验收。
2. 收敛有效读取修正，保留独立低速回归基线，简化纯诊断逻辑，不删除仍承担协议作用的保护。
3. 在测试区单独推进相机供数、LCD带宽、读速与调度，逐项定值图案验证；最后统计屏幕实际帧率、丢帧/错误和长期动态稳定性。
