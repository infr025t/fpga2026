# 动态图像异常：写屏前全图证据
用户照片显示整块错位/重复、白色亮点和大量浮雕噪声。不能用22.5fps或源到LCD CRC一致认定图像正确。
1. 保留并暂停dynamic_raw_live_01，约8100帧全部记录像素数/行数及源到sink CRC自洽；这些对摄像头FIFO内容无真实性保证。旧中央16行快照不能覆盖全场。
2. 新全幅概览只被动抽取160×120（原生640×480仍完整读取/显示），内部RAW50帧全CRC和概览逐像素参考均通过。overview_scene_01明显孤立白点已经在FPGA输出，显示器不是这部分问题的唯一来源。
3. 亮点数值多数接近bit7异常。把单次采样从读上升后30ns后移到40ns，仍16.667MHz、不双采、不改数值核心、不清bit7。35ns压力模型旧版红/新版绿，VGA环绕/暂停模型绿；实际外部延迟未测，压力测试不等于线缆实测。
4. 新版500帧固定色条整帧CRC通过，仍22.5077fps。三次各200帧实拍后导出的全幅抽样图中>=250像素数均0，相比30ns基线69/10/0。场景和曝光未严格控制，只能记录改善迹象，不能断言全部白点消失。
5. sample40_scene_03（暂停显示201帧）的底部出现显著浮雕/低对比矩形区，写屏前已存在，与用户描述同类。sample40_three_frames.png右图可见。这否定“只是LCD”的解释，也否定40ns已修复全部异常。
结论：采集侧数据错误仍在，具体摄像头FIFO写入、字节相位/读指针或读采样电气时序尚未完全区分。固定色条统计不能覆盖真实动态异常比例。当前保留sample40候选并暂停，未改main；没有将错误区域复制/重排/滤除作为修复。
