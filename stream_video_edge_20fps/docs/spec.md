# 当前设计与接口

主链：`camera_fifo_video → video_core_adapter → video_lcd_sink → NT35510`。系统逻辑使用 100 MHz 时钟；FPGA 负责采集调度、算法和写屏，PC 只读诊断数据。

## 摄像头连续读取

- 传感器配置使用 PLL×6、CLKRC=1，AEC/AGC 开启。摄像头自然场速率与处理吞吐分别计数，历史板测约 22.51 fps。
- AL422B 以连续写入周期跨越多个传感器场。首次启动等待 32 行信用；每完整行增加 1280 字节信用，用 32 位无符号差值跟踪已提交写入量与读取量。每帧完整消费 `640×480×2=614400` 字节，帧间不重置 FIFO。
- `RCLK=100 MHz/6≈16.667 MHz`。六拍相位中，phase2 发出 RCLK 上升沿；下一周期 phase0 在其后 **40 ns** 进行一次 IOB 采样，下一拍再消费样本。这里的 40 ns 是 RTL 发出边沿到采样使能的间隔，外部器件实际建立时间还要扣除输出、布线与输入延迟。
- `READ_GUARD=129`：信用不足时暂停发出读取周期。首次 RRST 释放前已预取的第 0 字节同样经过 IOB 采样；实际 FIFO 相位按 `Y_BYTE=0` 取 Y，保留前一个相邻字节供诊断。SCCB 格式名称与 FIFO 起始字节相位分开处理。
- 暂停/切换内部源在已接纳帧完成后停止后续写入，恢复时重新预备。已发出的 `camera_admitted` 必须由摄像头和显示两端共同接纳，不能被同拍新暂停请求撤销。

当前 XDC 保持外部输入延迟最大 23 ns、输入起点 `max_delay -datapath_only` 总预算 28 ns（包含外部 23 ns），即内部数据路径预算 5 ns；数据输入使用 `IOBDELAY NONE`。这些约束与功能仿真不代替当前接线的示波器波形测量。

## RAW 与 Gaussian＋Sobel

RAW 直接传递 640×480 的 Y 值。EDGE 先做一次 3×3 Gaussian，核为 `[1 2 1; 2 4 2; 1 2 1]/16`，整数实现先加 8 再右移 4 位；随后做 3×3 Sobel，以 `|Gx|+|Gy|≥128` 输出 255，否则输出 0。

当前接口保留每侧裁去 5 像素的坐标约定，因此 EDGE 为 630×470。行窗口、RAW 对齐数据和坐标随 valid 一起推进；源空拍不生成新像素。核心没有 ready/backpressure 输入。

## 写屏与保护

RAW 位于屏幕 x=80..719、y=0..479；EDGE 位于 x=85..714、y=5..474。切换尺寸前清背景。灰度转换为 RGB565，经八位 8080 总线分两字节发送。当前 setup/low/hold 均为 2 个系统周期，gap=0；连续数据每像素 120 ns，与每两个 FIFO 字节 120 ns 的读取节奏匹配。

显示入口用有限队列吸收局部相位差，检查坐标、像素数、溢出及显示队列输入/输出 CRC。完成事件在源结束、队列排空、最后写屏事务完成后提交。摄像头检查行数、FIFO 占用、超时和场外行；首个采集错误及其时序上下文被锁存，便于复现，错误后不会继续接纳正常摄像头帧。

内部图和固定色条具有参考 CRC。普通连续构建遇到硬件参考不符会锁存停止；`STAT_FRAMES>0` 的统计构建累计参考失败并在指定完成帧数后停止，主机同时检查失败计数。

## 被动诊断

默认构建保留 VIO、色条逐像素比较、JTAG 概览快照和 UART 配对概览。当前 JTAG 概览按 x=3,7,…、y=0,4,… 取样，RAW 为 160×120；EDGE 为 157×118。快照每样本两字节、每次 JTAG 读 32 个样本。

真实摄像头 RAW 的两个字节分别为显示 Y 与前一个相邻 FIFO 字节；EDGE/内部图的快照配对当前输出与同位置原始灰度。UART 只发送摄像头 RAW（含色条）的 160×120 配对概览。诊断队列满时丢诊断包并计数，不修改显示像素、不反压主链。具体字段见[调试说明](debug.md)。
