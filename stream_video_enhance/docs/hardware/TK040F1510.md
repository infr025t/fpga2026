## 8位8080协议与像素格式

NT35510的芯片接口模式 `IM3…IM0=0000` 为8位8080，使用原生 `D[7:0]`。转接板的 `IM1/IM0=00` 对应8位模式；这只是原理图选项定义，不代表实物已经按此焊接。

- `CS_n=0` 时接口被选中，控制器在 `WR_n` **上升沿**采样。
- 命令地址为16位，`RS/D_C=0`，先高字节、再低字节。例如 `0x2C00` 为 `2C,00`。
- 寄存器参数同样为16位，`RS/D_C=1`，先高字节、再低字节；`0x0055` 为 `00,55`。
- GRAM像素采用RGB565，每像素两个数据字节，高字节先发，不能把寄存器参数的零扩展规则误用于像素高字节。
- 写专用实现将 `RD_n` 保持高电平。它不进行器件ID或寄存器读回，`init_done` 只表示所选初始化序列已发送完成。

灰度到RGB565的映射为 `R=Y[7:3]、G=Y[7:2]、B=Y[7:3]`。设置 `3A00=0055`，使MCU格式为16位；`3600=00A3` 沿用该面板示例的横屏设置。其中MV=1，交换行列；MY=1、MX=0、RSMX=1、RSMY=1。该值不替代真实面板的方向、颜色和首尾角标检查。

原示例初始化先设置竖屏窗口，再在末尾切换横屏。实际绘制前必须重写完整横屏窗口，不能沿用先前的479/799边界。

### 动态窗口的规范化

芯片p285/287对 `2A00…2A03`、`2B00…2B03` 的非MIPI参数上字节均列为 `00h`。每个寄存器的低8位只携带坐标的一个字段，因此本项目动态窗口采用以下规范写法：

| 目标 | 高字段寄存器与参数 | 低字段寄存器与参数 |
|---|---|---|
| X起点0 | `2A00=0000` | `2A01=0000` |
| X终点799 | `2A02=0003` | `2A03=001F` |
| Y起点0 | `2B00=0000` | `2B01=0000` |
| Y终点479 | `2B02=0001` | `2B03=00DF` |

厂商动态坐标函数可能把完整 `0x031F` 传给低字段寄存器 `2A03`，使总线上出现 `03,1F`。手册没有承诺该上字节03被忽略，本项目不据此称其为规范行为；动态写窗明确零扩展低字段为 `00,1F`。这是对示例未掩码坐标写入的显式差异，不改变最终有效坐标。原初始化序列的来源与任何规范化由profile和生成检查追溯；不宣称所有厂商扩展寄存器均已由通用芯片手册逐项认证。

## 时序与复位

芯片p363的写接口最低要求如下，单位均为ns：

| 参数 | 最低要求 | 100MHz默认实现 |
|---|---:|---|
| WR周期 | 33 | 使用完整建立/低/保持/间隙状态，不采用1拍高低脉冲 |
| WR低电平 | 15 | LOW=3拍，30ns |
| WR高电平 | 15 | 保持、下一字节建立及间隙共同满足 |
| 数据建立 | 15 | SETUP=2拍后进入低电平阶段，至采样上升沿仍保持稳定 |
| 数据保持 | 10 | HOLD=2拍，20ns |
| D/C写建立/保持 | 0 / 2 | 整个16位字锁存，两个字节期间不改变 |

默认参数为 `SETUP/LOW/HOLD/GAP=2/3/2/1`。总线按100MHz设计；`CLK_HZ` 参数仅用于初始化毫秒计数，修改它不会自动换算总线脉宽。仿真可用较小 `CLK_HZ` 加快等待阶段，但不能将该仿真参数当成另一实际时钟的板级认证。引脚延迟、线缆负载、实际边沿和板端建立/保持仍需实现约束与波形实测。芯片还要求输入上升/下降时间不大于15ns，RTL计数本身不能证明这一电气条件。

芯片p372规定复位低脉冲至少10μs，释放后发送普通命令至少等5ms，并另列Sleep Out的120ms限制；p272规定Sleep Out后至下一命令至少5ms，Sleep In到Sleep Out至少120ms。本项目选择复位低20ms、释放后120ms、发送Sleep Out后再等120ms。后一个120ms是保守/面板初始化策略，**不是把芯片5ms最低要求改写成120ms**。厂商C代码的空循环不能直接换算为FPGA毫秒计数。

读ID和GRAM有不同且更慢的时序：ID周期至少160ns，GRAM周期至少400ns；相应访问最大值为40ns和150ns。当前写专用实现不包含这些读周期，不把RD常高当成读回验证。

## 转接板连接与电源边界

以下为转接板PDF p1的 **P1端子编号**，不是Basys 3封装引脚或Pmod排针编号：

| P1端子 | 信号 |
|---|---|
| 16…23 | D00…D07，按位递增 |
| 11 / 12 | CS / RS |
| 13 / 14 | WR / RD |
| 15 | RST |
| 38 | BL_CTR，背光开关控制 |
| 40 | 3V3 |
| 2 / 39 | GND |

P1 pin1标为5V，但图中没有据此可明确确认的LCD 5V供电路径；不能只按该标签推断给LCD供电。3.3V网络同时连接VCI、IOVCC和LEDA，`BL_CTR` 是开关器件门极控制，GPIO不承担背光供电电流。原理图没有给出足够信息以直接验收整个背光电流与限流预算；仍须核实实际板版、供电和背光配置。

接口选择中R2/R4是到地选件，R1/R5是上拉选件。原理图中存在元件/选项不等于实物已焊接；8位模式应确认实际IM状态，不能由软件文件名替代。

本轮不分配Basys XDC：用户尚未给出开发板到P1的实际线序。旧相机使用JA和JC，可将JB/JXADC作为剩余接口的候选，但不是已确认接线，更不能把上表P1编号直接当FPGA脚号。

### 模组PDF内的冲突

模组p5机械图实际标注FPC14=RS/SCL、15=CS、16=RESET、33…40=DB7…DB0、47=WR、48=RD、49/50=NC；p9–10文字表却将WR/RD写成NC并把49/50列为IM。MCU接线使用p5图与转接板原理图交叉核对，不采用混入RGB版内容的文字表。

p5注明VCI/IOVCC为3.3V，p9又列出IOVCC至3.3V的范围，但p6通用DC表写有较低的电压范围；p5背光说明写串联，实际图和p6表则为并联。这些冲突已保留在来源记录中，不能据矛盾的裸屏通用表直接计算本转接板的安全供电需求。

## 完整画布与带宽优化

处理核心输出632×472，对应原图坐标x=4…635、y=4…475。将640×480逻辑画布居中放在800×480面板上，外部左右各80像素，所以有效图映射到面板 **(84,4)…(715,475)**，没有缩小或丢弃有效像素。

初始化和恢复时整屏清黑一次，之后只重写这个有效窗口，保留所有黑边。每帧有效载荷为 `632×472×2=596,608 B`，相比800×480整屏的768,000 B减少22.32%。灰度只在写屏时转换为RGB565，不为算法另建三色帧缓存。

默认总线背靠背发送的理想载荷上限约为每像素160ns，即6.25MPixel/s；相应有效区约47.73ms、整面板约61.44ms，实际还要考虑命令、握手和状态开销。这不是已经测得的实屏帧率，也不构成30fps承诺。

100MPixel/s内部源不能直接连接慢屏并指望小FIFO保存任意完整帧。是否选择一帧、允许的源突发/平均速率、有限缓存和异常恢复必须有明确包络；不能通过LCD ready反压主计算链，或把缩小预览作为完整VGA结果。本轮整幅画布自检采用独立、可等待总线的自检源，不能据此宣称主运行时已完成显示集成。

## TE、初始化状态与实物验收

芯片支持TE（p195–199），模组FPC11也有TE；但所给转接板把该处标为NC，没有将TE引出给FPGA。因此本轮不虚构TE输入或声称已经无撕裂。即使后续增加TE连接，也仍须证明写入带宽、刷新扫描与指针时序，TE本身不提供额外帧缓存或原子整帧提交。

没有完整帧算法缓存时，晚到源错误无法撤回已经写入GRAM的前缀；它必须计为中止，不能记作一次成功显示。重新清屏、重建窗口和重启写入的恢复行为，与主运行时的成功CRC报告分别验证。

### 独立屏幕自检的使用方式

顶层选择 `nt35510_bringup_top`，输入板载100MHz时钟。确认P1线序、电平、供电和IM配置后，另行编写匹配实际接线的XDC；当前没有可直接下载的新bit。上电或BTNC复位后，先执行复位等待及初始化，清黑整个800×480面板，再打开背光并重复绘制有效区域。

这个独立顶层的开关含义与主运行时操作表分开：

| 控件 | 屏幕自检含义 |
|---|---|
| BTNC | 复位屏幕与发送状态，重新初始化并清黑 |
| SW15=1 | 完成当前图案后暂停后续图案；SW15=0继续 |
| SW1:0=00 | 移动灰度斜坡 |
| SW1:0=01 | 16像素方格 |
| SW1:0=10 | 灰度阶跃 |
| SW1:0=11 | 固定中灰 |

图案在帧开始时锁存，帧中切换开关不混合两种图案。LED0=初始化发送完成，LED1=背景清黑完成，LED2=一次写入完成脉冲，LED3=忙，LED4=屏幕复位释放，LED5=背光控制，LED6=暂停开关，LED7=窗口错误脉冲，LED15:8=完成图案计数低8位。脉冲状态可能短于肉眼可见时间；`frame_done` 表示最后一个字已发送完成，不表示LCD扫描恰好完成，也不能据此称为无撕裂。
