## File/API map

`rtl/core_latency_pkg.sv` defines the measured module latencies and their sum. `rtl/token_pipe.sv` provides valid/payload delay includingzero-latency wire option and abort flush. `scripts/run_core_tests.py` discovers Vivado, generates vectors, runs compile/elaboration/simulation with timeout, requiresPASS markers and zeroerror diagnostics, writes machine-readable pertestresults. `sim/` benches use independent expected files; they may store complete test images (the synthesizable core may not).

The external core port contract is:

```systemverilog
module guided_core #(parameter integer W=640,H=480,EXTRA_ALIGN=0)(
 input wire clk,rst,abort,
 input wire [7:0] in_pixel,input wire in_valid,
 input wire [9:0] in_x,input wire [8:0] in_y,
 input wire in_sof,in_eol,in_eof,input wire [31:0] in_frame_id,
 input wire [10:0] epsilon,input wire [4:0] threshold,
 input wire [9:0] gain,input wire [1:0] view_mode,
 output wire [7:0] out_pixel,out_raw,out_base,output wire out_valid,
 output wire [9:0] out_x,output wire [8:0] out_y,
 output wire out_sof,out_eol,out_eof,output wire [31:0] out_frame_id,
 output wire arithmetic_error
);
```

Gain is integerQ8. Mode00RAW/01BASE/10DENOISE/11ENHANCE; DENOISE gain256. RAW/BASE still compute full chain for same latency. EXTRA_ALIGN is0 in production and1 for alternate fixed-latency verification, not padding to64. It counts actual output shift registers after enhancement; implement a single output register for1, not token_pipe LATENCY1 (which has two sampling registers under the specified observable-latency convention). Parameter validation is elaboration-time for W/H and simulation assertions for stable legal frame configuration; later ingress controller owns malformed-coordinate recovery.
