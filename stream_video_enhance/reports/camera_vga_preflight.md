# 现有 OV7670_FIFO 的 VGA 并发采集实施前审查

日期：2026-10-23。范围：只读源码、既有接线文档和原厂资料；本报告不授权或实现 RTL、改线、寄存器重配、下载或实板测试。主任务仍是软件模型门槛。

## 结论与证据边界

现有 OV7670 继续作为正式 640×480 输入候选，不要求购买另一摄像头。614,400 B 的 VGA YUV422 帧不能完整驻留于 393,216 B 的 AL422B，但有界并发读写可以绕过这个限制；容量本身不足以判定方案不可行。

“完成64个HREF有效行后，连续10 MHz读614,400字节、隔字节取Y、只选择部分物理帧”可以现在建立**参数化外设行为仿真**，先证伪错误调度并找出安全包络。它还不是能直接上板的参数组合。未掌握模块实际时钟，不影响仿真合成时序场景；却不能把某个合成场景通过写成实际模块通过，或承诺持续30 fps。

更关键的是，理想FIFO容量检查只是必要条件：必须建模 AL422B 的读写复位、缓存/尾部提交、真实读使能接法和后续 VSYNC。仅模拟无延迟队列会漏过本方案最危险的错误。

## 接口足够讨论候选，但没有暴露真实FIFO占用量

现有引脚是 FIFO DO[7:0]→JA、VSYNC→JC3、WEN/WR→JC4、RRST→JC7、RCLK→JC8、RST→JC9、HREF→JC10，另有SCCB。手册记录 WRST 接模块VSYNC，OE/PWDN接地；没有证明 FPGA 可控制 /RE，也没有证明原始PCLK已引到FPGA。`cam_wen` 是模块级高有效允许，不能直接当成芯片低有效 /WE：模块仍必须完成 HREF 门控与极性转换。

HREF高/低宽度及行周期可以用100 MHz同步观察；它们提供到达曲线的时间包络，但不直接证明每行恰有1280个有效WCK采样，也不提供芯片满/空标志。已有240/240/0行记录属于旧QVGA设置；VGA配置后必须重新检查480行，不能继承旧计数作为VGA证据。

## 到达/服务/占用的可执行推导

以下为本报告推导，均按FIFO**字节**计算，不能先抽Y后把占用减半。令：

```
L = 1280 bytes/line
H = 480 lines
N = L*H = 614400 bytes/frame
C = 393216 bytes
g = 128 bytes                 # 保守保护距离，实际模型另计缓存状态
fR = 10e6 reads/s             # 候选
s[j] = 第j行首个有效写入时刻，j=0..479
w[j,k] = 第j行第k个有效字节的实际WCK采样时刻，k=0..1279
A(t) = count(w[j,k] <= t)     # 被选中帧累计真实有效写入
R(t) = 已发生的有效读指针推进数；不是pixel_valid数
Q(t) = A(t)-R(t)
```

把所有写入、读出、复位事件按实际相位逐一排序；同时间事件不得总是有利排序。读写指针均须按 C 取模，不能按2^19取模；未卷绕的A/R用于证明同一帧的数据代际。

当读到“正在更新的新帧”时，以保守新数据区间检查：每次有效读之前已有足够写入领先，且任一写/读事件后的 `Q <= C-g`。用统一的 `g <= Q <= C-g` 作流动阶段包络可提前筛错；等号/首字节采样采用同一计数约定并预留边沿裕量。`Qmax` 是对全部事件取最大，不只是检查帧尾。

### 固定行时序时的精确候选公式

假设仅用于仿真的等长行：相邻行起点间距P，有效写时长h=L/fW，行消隐b=P-h≥0。第64个完整行结束为 `c[63]=63P+h`。实际第一次有效读还要经过同步检测、RRST建立/保持及初始读时序，令总延迟为δ：

```
t0 = 63P+h+δ
tE = 479P+h
tE-t0 = 416P-δ
R(t) = clamp(floor(fR*(t-t0))+edge_convention, 0, N)
Q(tE) ≈ N - fR*(416P-δ)
```

δ不是可以忽略的RTL细节：延后读出可改善欠读却增加最高积压；同步观测误差、RRST脉冲和相位必须放进模型。64完整行意味着81920字节初始写入，前提是每行字节数和门控已成立。

只检查帧尾上界、暂取δ=0，有：

```
P >= (N-(C-g))/(416*fR) = 53.2 us
480P >= 25.536 ms
```

这对应已有评估中约25.54 ms的平滑必要条件，但这里明确了P与实际首末有效写入跨度 `479P+h` 的区别。它不是充分条件。

在相邻相同相位的行端点，占用变化为 `L-fR*P`。若 fW>fR，行有效段Q上升、消隐段下降，故应检查每行首写前/行尾以及读启动点；若 fW≤fR，行内也可能下降。一个常被漏掉的最低领先量是：在第64行完成后尚未出现第65行写入的消隐中，最多会额外读走 `fR*b` 字节，启动时81920字节并不能替代后续全部消隐检查。长行间隙、缺行、AEC改变行/帧时序或δ跨行都需要逐事件检查。

仅作筛选，要求帧尾尚保持128字节新数据领先还给出 `P <= (N-g)/(416*fR) ≈147.662 us`；逐行最低点可能收紧此范围。**此下界保护不能生搬到最后128字节排空**，尾部必须通过下一节的提交/复位模型单独验收。

## 必须显式建模的物理陷阱

依据 [AL422B datasheet](https://www.haoyuelectronics.com/Attachment/OV7670-Module-A/AL422b.pdf) §7.4、§8.1、§8.3，关键约束简列如下：393216×8容量、独立读写、128周期新数据距离；复位随对应时钟采样，禁用周期中的复位存在延后执行；WRST涉及写缓存提交，RRST涉及预取；OE不停止读指针；读写时钟应连续，至少1 MHz，较快时钟承担刷新；最大输出访问延迟15 ns。具体读写/cache行为应按上述章节建立，不能由理想FIFO类替代。

复查原文定位：PDF第4页为容量/独立读写；第7页§7.4为TAC及复位建立/保持；第9页读写复位波形；第14页§8.1为禁用期间延后复位及输入缓存提交/输出预取；第15页为RE/OE区别及新数据读距离；第16页§8.3.1为连续时钟/刷新；第17页§8.3.2～8.3.4为旧/新数据访问限制与单帧复读。这里页码与文件印刷页码一致。

1. **RRST不能过早释放然后仅忽略数据。** 假定/RE常开，则每一个RCLK都推进读地址。先随意读旧数据、等待64行后继续新数据，既破坏首地址，又可能踩中手册§8.3.2的旧数据/新数据访问限制。候选应在预写完成后执行一次规范RRST，随后从确认的byte0读到结束。启动前的无效读必须被该次RRST隔离；不能将短暂低电平或“把计数器清零”等同芯片指针复位。

2. **WRST与HREF门控的组合未知。** 模块WRST接负极性VSYNC，在有效帧内为高、消隐内为低。此时HREF为低，若模块门控让芯片/WE禁用，不能无条件假设复位已在该VSYNC边沿生效。需确认模块逻辑是否提供复位的有效采样、何时执行延后复位，以及首个有效字节是否被正确保存。旧QVGA成像是有价值的基线，但没有给出VGA并发期间的波形证明。

3. **有限帧尾不能用“Q最终归零”证明正确。** 最后部分字节可能仍在写缓存；原RTL的时间等待不等于有新的有效写入或一次实际生效的WRST。模型必须区分已接收A与已提交/可预取的字节，证明最后128字节和最终Y能读到同一帧的新内容。若要利用帧尾WRST提交，必须核验它在WEN/HREF组合下真正执行，以及不会扰乱正在进行的并发读取。不能把 `Q>=128` 的新数据流规则强制延长到N字节全部排空后又宣布不可能，也不能简单删掉该断言宣布可用。

4. **选中帧结束后还有物理帧。** 排空过程中保持WEN关闭，后续VSYNC仍然施加WRST。写指针复位本身不等于擦除整片RAM，也不能无依据断言它必然破坏所有未读数据；但缓存提交/延后复位与未读尾部是否相容需要模型证据。下一次允许写入必须在当前帧读完或明确废弃之后，重新对齐完整物理帧。不能在614400字节尚未读完时因下个VSYNC自动重开WEN。

5. **10 MHz不能只改READ_PERIOD。** 原代码在 `phase==READ_PERIOD/2-1` 拉高RCLK，在 `phase==READ_PERIOD-5` 采样。READ_PERIOD=50时相隔21个100 MHz周期，约210 ns；改成10后只有1周期，即10 ns，小于芯片15 ns最大TAC，尚未计走线。需选择有明确余量的采样相位、保证RRST与RCLK的建立/保持，再检查下一上升沿前的数据保持。旧XDC `divide_by 50`、20/19多周期和25 ns输入延迟预算都不能原样当成10 MHz证据；要按新采样边沿重建，不能单纯扩大例外。

6. **刷新与暂停。** 暂无已证实/RE控制，不能靠任意停RCLK吸收慢行或下游暂停。若始终自由运行并仅用pixel_valid屏蔽输出，芯片读指针仍前进，必须计入R。复位期间的时钟也需满足物理规范；原系统复位时RCLK被拉低的历史行为不能作为长期暂停时钟方案。

## 下一步可用的失败即丢帧仿真契约

这是一份后续测试规格，不是本次已实现或已通过的测试。

### 外设模型

- 参数化fW、每行1280次有效写入、480行、HREF高/低时间、VSYNC极性/宽度、帧间隔、时钟漂移和起始相位；保留WCK在消隐时自由运行。单独模拟模块 WEN→/WE 逻辑，不能只接理想队列push。
- 用393216字节环形存储、展开的frame/row/byte序号标签和独立读写指针；至少覆盖一次地址回卷。数据模式应能发现掉字节、重复、奇偶Y交换和跨帧拼接；仅8位递增值不足以唯一识别地址回卷，标签只在测试台使用。
- 模拟真实/RE接法、OE接地、WRST随每次物理VSYNC、同步复位及延后行为、输入缓存提交与输出预取；把芯片规范不保证的读取结果标为X或旧数据并立即报错，不能总返回期望值。
- 每次有效读检查对应位置已提交且属于目标帧，保存Qmin/Qmax、最小安全距离、首末字节时间及错误发生位置。对无法可靠建模的缓存边界，明确报告`MODEL_UNRESOLVED`，不记PASS。

### 适配器可观察契约

- 配置/时序包络未确认时仅记录诊断，不发布“摄像头通过”。接受采集请求后，从完整帧边界开始，WEN窗口覆盖恰好480个完整有效行；64行阈值基于下降沿且不接受半行启动。
- RRST释放后，全部有效读严格从byte0至byte614399，每两字节产生一个Y，共307200像素。不得因核心或预览忙而暂停物理读；核心入口溢出视为本帧失败。
- 源帧成功需要两项都确认：完整480行物理帧已经结束，且614400个字节完成读出并通过源契约。`pixel EOF`/最后一次读不能代替最终source status；若此前已流入核心的帧后来失败，必须由既有错误恢复路径废弃其结果并更新诊断，禁止导出为成功新帧。
- 发现少/多行、HREF/VSYNC异常、超时、时序包络越界、入口溢出或仿真占用/代际违规时，关WEN、抑制后续像素并发布明确失败；保持刷新时钟。废弃该帧后等待干净边界，执行可证明的重新复位/预写流程再重试。错误不能静默变成上一帧内容。

### 最小测试矩阵

1. 小帧用于控制定位，但不能替代VGA容量测试；正式VGA至少覆盖上述两个合成可行包络及快写溢出/慢写欠读反例，且完整比较307200个Y。
2. 扫描行内读写相位、RRST边沿、δ上下界、最长消隐、快慢时钟容差与首末行。至少一次在每个易错边沿前后移动一个核心周期。
3. 注入缺行、多行、半行、消隐变长、VSYNC提前/丢失、读出中复位、最后128字节未提交、下一物理帧WRST、下一帧提前开WEN、/RE绑定与假设不符。每个反例都必须触发失败，随后验证新完整帧恢复。
4. 验证自由运行时钟、WEN关闭后的继续排空、长期跳帧、读写地址模C回卷、异常后无旧图冒充。CRC只能验证已采集流的传输一致性；不能单独证明源字节来自正确物理帧。

### 可由现有信号增加的诊断

后续诊断建议记录：VGA寄存器读回快照、VSYNC高/低宽度、完整HREF行数、HREF高宽与行周期的min/max、WEN相对首末HREF的边界、读启动时刻/完成时刻、实际读计数、跳帧/丢帧原因、入口峰值。由每行1280字节假设推导的占用必须叫`predicted occupancy`并带包络版本；在没有PCLK/芯片标志观测时，不能报告它为实测满/空。

## 真正阻挡上板承诺的缺项

| 缺项 | 为什么需要 | 不需要假定的新硬件 |
|---|---|---|
| 实际输入时钟、VGA配置下PCLK/WCK范围和行时序 | 决定突发率、Qmin/Qmax和刷新 | 先核对现模块标识/资料，并用现有HREF/VSYNC诊断缩窄包络；没有原始PCLK证据时明确剩余不确定性 |
| 模块HREF/WEN极性与门控、/RE真实绑定 | 决定指针何时推进、复位是否执行 | 先核对同一模块接法/原理图，不从AL422B芯片pinout推定模块引出 |
| WRST在帧首/帧尾及后续VSYNC的实际行为 | 决定首地址、尾部提交、并发读取代际 | 先形成外设模型并列明需要的波形；具体缺信号再与用户讨论 |
| 10 MHz读出电气/约束与正确采样相位 | 旧10 ns采样间隔不满足TAC上界 | 先修订时序设计并仿真，再做新综合/布局布线与实板证据 |
| 新VGA窗口/数据字节顺序与全帧完整性 | 行数正确仍可能丢首字节或UV/Y错位 | 先寄存器读回/已知图案模型，后续按同一候选配置验证 |

这些是**实际采集发布门槛**，不阻塞当前软件参考模型，也不阻塞写参数化外设仿真规格。若模型证明当前引脚组合无法可靠结束/恢复一次并发捕获，应报告具体失败机制和所缺控制，不提前把结论写成“必须换摄像头”。
